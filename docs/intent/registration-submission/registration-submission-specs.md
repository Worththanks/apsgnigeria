# Organization Registration Submission Requirements

- [ ] **REG-SUBMIT-001**: When an applicant continues from the membership choice page, the registration page shall accept exactly one of APSG, APSG Youth Wing, CWDI, or CWDI Youth Wing and shall block review or submission when no choice is selected.
- [ ] **REG-SUBMIT-002**: When a registration lookup or submission runs, the registration page shall query and write only the registry mapped to the single selected membership choice.
- [ ] **REG-SUBMIT-003**: When the selected organization's registry contains an exact normalized phone, first-name, and last-name match and the selected membership is that organization's Youth Wing, submission shall set only that member row's Youth Wing flag to true and shall preserve the member's profile, residence fields, and organization registration number.
- [ ] **REG-SUBMIT-004**: When the selected organization's registry contains a phone match with a different stored name and the applicant verifies that candidate using the candidate's organization registration number and phone while selecting that organization's Youth Wing, the registration page shall update only the verified candidate's Youth Wing flag, preserve the stored profile, residence fields, and registration number, and show the existing organization ID in a success receipt.
- [ ] **REG-SUBMIT-005**: When an exact-match or verified existing member already has the selected organization's Youth Wing flag, the registration page shall not change the member row and shall show a successful already-enrolled outcome with the same organization registration number.
- [ ] **REG-SUBMIT-006**: When the selected registry has no phone match and the applicant selects APSG Youth Wing or CWDI Youth Wing, submission shall create one full member row in the selected organization's registry, set its Youth Wing flag to true, issue the registration number for that member's explicitly selected residence, and identify the person as both a full member and a Youth Wing member.
- [ ] **REG-SUBMIT-007**: When the selected registry has no phone match and the applicant selects general APSG or CWDI membership, submission shall create one full member row in only that registry with its Youth Wing flag false and issue the registration number for that member's explicitly selected residence.
- [ ] **REG-SUBMIT-008**: When a registration completes, the success receipt shall show exactly one selected organization's logo and name, the selected membership label, one outcome, and one organization registration number.
- [ ] **REG-SUBMIT-009**: When the applicant chooses Done on the success receipt, the registration page shall clear the completed form values and membership selection and return to the four-option membership choice page for a separate later registration.
- [ ] **REG-SUBMIT-010**: If the selected registry or its required write operation is unavailable, or the final duplicate check finds an unresolved different-name phone match, the registration page shall not show success, shall not create a second member row, and shall keep the current registration available for retry or coordinator resolution.
- [ ] **REG-SUBMIT-011**: When the registration page runs on localhost, it shall block registration uploads, registration-number allocation, member-row inserts, and Youth Wing updates, including updates after candidate verification.
- [ ] **REG-SUBMIT-012**: When an existing-member candidate is verified for general membership, the registration page shall preserve the verified candidate's organization-specific member-portal handoff without creating or changing a member row; when the page runs on localhost, the destination member portal shall be view-only.
- [ ] **REG-SUBMIT-013**: When a CWDI registration requires a member-row lookup, Youth Wing update, or new membership, the registration page shall use a CWDI-specific server-side database operation and shall not write directly to `public.cwdi_members` from the browser.
- [ ] **REG-SUBMIT-014**: When a new APSG or CWDI member row is created for any of the four membership choices, submission shall save the trimmed Middle Name in `middle_name` and the selected Gender in `sex`, using `null` for blank values; these fields shall not change existing-member matching, and reusing a member row shall preserve its stored personal details.
- [ ] **REG-SUBMIT-015**: Before uploading registration documents, submission shall check the selected registry with the snapshotted phone and names, reject unresolved different-name matches, and skip new uploads when an existing matching membership is reused.
- [ ] **REG-SUBMIT-016**: If upload or submission fails, the registration service shall remove only files created by that registration attempt and confirmed unattached; if a write result is uncertain, it shall verify the saved record before cleanup, preserve referenced files, and retain unresolved attempt files for retry without reporting an unconfirmed success.
- [ ] **REG-SUBMIT-017**: While a registration submission is in flight, the page shall process one snapshotted operation, lock form and review controls, and restore controls on completion or failure; an existing member's success receipt shall use the stored profile.
- [ ] **REG-SUBMIT-018**: When an APSG or CWDI registration operation writes a member row, the database shall serialize the selected organization's full canonical E.164 phone match and number allocation, preserve existing profile and residence fields on reuse, and return the saved organization registration number for the receipt.
- [ ] **REG-SUBMIT-019**: When a new APSG or CWDI member row is created, the organization registry shall store the canonical E.164 phone, explicit ISO-3166-1 alpha-3 `residence_country_code`, and applicable `residence_city` and `residence_state_province` separately from the existing Nigerian State/LGA/Ward fields; the migration shall add these residence columns as nullable and shall leave legacy rows without verified residence unchanged.
- [ ] **REG-SUBMIT-020**: When a new member selects Nigeria (`NGA`) as residence, the selected organization's registration operation shall retain the existing Nigerian State/LGA/Ward requirements and Nigerian registration-number format.
- [ ] **REG-SUBMIT-021**: When a new member selects a valid non-Nigeria ISO-3166-1 alpha-3 residence, the selected organization's registration operation shall require current city and state/province, retain optional Nigerian home State/LGA/Ward separately, assign the Diaspora chapter, and issue `APSG/DIA/<ISO3>/<year>/<serial>` or `CWDI/DIA/<ISO3>/<year>/<serial>` in that organization's registry.
- [ ] **REG-SUBMIT-022**: When an APSG or CWDI Diaspora registration is processed, the selected organization's server-side operation shall validate the residence code against server-owned country data and derive the chapter, ISO3 ID segment, year, and registration number; it shall not trust browser-supplied chapter, ISO3 segment, year, or registration number.
- [ ] **REG-SUBMIT-023**: When an APSG or CWDI Diaspora registration allocates a serial, it shall atomically increment only that organization's separate counter for the residence ISO3 and server-selected year in the same transaction as the member insert; it shall not read or increment the other organization's counter, a failed insert shall roll back the counter, and simultaneous allocations shall receive distinct IDs.
- [ ] **REG-SUBMIT-024**: When an APSG or CWDI Diaspora registration is allocated, the database shall use the Africa/Lagos calendar year and a serial padded to at least six digits, expanding beyond six digits without truncation.
- [ ] **REG-SUBMIT-025**: When an APSG or CWDI registration operation performs its final duplicate check, it shall compare full canonical E.164 values, recognize equivalent legacy Nigerian national and `+234` values, and never treat two international numbers as equal solely because their last 10 digits match.
- [ ] **REG-SUBMIT-026**: When the registration service retains uploaded files for retry, its identity key shall include the selected organization and the full canonical E.164 phone so international numbers sharing their last 10 digits do not reuse each other's upload state.
- [ ] **REG-SUBMIT-027**: When the APSG or CWDI registration operation validates a residence ISO3 code, its server-owned country directory shall use the same versioned country dataset as the local registration selectors and shall reject any code absent from that directory.
- [ ] **REG-SUBMIT-028**: When public APSG or CWDI registration uses a Diaspora country directory or serial counter, browser roles shall execute only the selected organization's secure registration operation and shall have no direct read or write access to the country directory or either counter table.
- [ ] **REG-SUBMIT-029**: When the selected organization's registration operation finds an existing exact member for a general-membership choice, it shall preserve that member's Youth Wing classification, profile, residence, and organization registration number.
- [ ] **REG-SUBMIT-030**: If the selected organization's matching member row has no valid registration number for that organization, then registration shall not issue a replacement number or update Youth Wing status and shall return a coordinator-correction error.
- [ ] **REG-SUBMIT-031**: When the APSG or CWDI registration operation receives a new-member phone number, it shall require canonical E.164 syntax and reject malformed input before duplicate checking or registration-number allocation.
- [ ] **REG-SUBMIT-032**: If an APSG or CWDI registration operation commits a new member row but its response is lost, then retrying the same organization, canonical E.164 phone, and name shall return the existing row and registration number without inserting a duplicate or advancing the Diaspora counter again.
- [ ] **REG-SUBMIT-033**: When the selected organization's operation creates a new non-Nigeria member, it shall store the optional canonical Nigerian contact number and preferred-contact value as a paired contact record; omitted, empty, or whitespace-only values shall normalize to `null`, and a partial pair shall be rejected.
- [ ] **REG-SUBMIT-034**: When the selected organization's registration operation receives a Nigerian contact pair, it shall enforce canonical E.164 syntax, the `+234` prefix, difference from the primary phone, and a preference of `primary` or `nigerian`; the form's bundled phone utility shall validate the Nigerian country-specific digit pattern before submission.
- [ ] **REG-SUBMIT-035**: When a new member selects Nigeria (`NGA`) as residence, the selected organization's registration operation shall require both diaspora-only contact fields to be `null` and shall reject a submitted Nigerian contact number or preference.
- [ ] **REG-SUBMIT-036**: When APSG or CWDI registration matches or verifies an existing member, the operation shall ignore any submitted Nigerian contact number and preference and preserve the stored primary phone and contact pair; an existing-member success receipt shall use the saved contact values and state that enrollment did not change the profile or contacts.
- [ ] **REG-SUBMIT-037**: When APSG or CWDI registration checks identity, conflict, authentication, recovery, retry identity, or registration-number allocation, it shall use only the established primary-phone identity and shall not use the Nigerian contact number as a key.
- [ ] **REG-SUBMIT-038**: When the registration client needs saved profile details for an existing-member receipt or upload reconciliation, it shall use only the existing phone-and-registration-number-verified member read; the registration operation response shall contain only `status` and `reg_number`, with successful statuses limited to `registered`, `youth-wing-added`, `already-youth-member`, and `already-member`, and `conflict` containing no registration number; invalid input or unavailable operations shall return an RPC error, and the client shall not use a broad member-table read.
- [ ] **REG-SUBMIT-039**: When the APSG/CWDI registration migration sequence is applied, `diaspora_membership_flow.sql` shall run after `phase2_registration_reliability.sql`, `cwdi_membership_schema.sql`, and `registration_personal_details.sql`; each migration shall apply transactionally, the release maintainer shall verify every prerequisite against the reviewed baseline before application, and an earlier Nigeria-only registration RPC source shall not be applied afterward.
- [ ] **REG-SUBMIT-040**: When `sql/diaspora_membership_flow.sql` is prepared, it shall add nullable `nigerian_phone_e164` and `preferred_contact_type` columns to both organization registries and database constraints enforcing canonical E.164 syntax, the `+234` prefix, difference from that row's primary phone, and valid number/preference pairing, without backfilling legacy records.
